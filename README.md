# 烘焙坊 · 烤箱设备与面包批次

烘焙坊生产管理：管理烤箱设备、面包配方，并以看板方式排产烘焙工单（待烤 → 烘焙中 → 已出炉 → 已质检），质检完成后出货（门店 / 外卖）。

## 生产排产（建议顺序）

侧栏「排产」把全部「待烤」工单排成可解释的建议顺序，所有计算在后端完成（前端只提交优先级序列，不自行排序/推算）：

- 建议顺序：默认按 交付截止（早优先）→ 配方耗时（短优先）→ 创建时间 排序；逐单给出预计开始/完成时间、占用烤箱、容量说明（占用 x/y 盘、占满整炉、原挂炉容量不足）与截止风险（紧张/无），并附排入原因（顺位依据、为何选该炉、原挂炉为何被替换）。
- 跨烤箱容量：故障炉不可排；占用中的烤箱按炉上烘焙中工单的预计出炉时刻释放；同刻可排时选最小可容纳炉。工单可建议改挂其它炉（只是建议，不改写挂炉归属）。
- 未排入区：没有可用烤箱、容量不足（容量预警）、预计逾期的工单留在未排入区并说明原因，不会伪装成已安排；预计逾期的工单不占用炉位。
- 调整与保存：拖动卡片（或上移/下移）调整优先级，效果经后端实时重算；「保存排产版本」落库为新版本。已开始/已完成的工单锁定不可拖动，后端同样拒绝其进入优先级序列。
- 只影响建议：排产只写 schedule_version / schedule_item，绝不改写工单状态、挂炉归属与故障接管结果。
- 过期与重算：版本保存排产输入指纹（烤箱状态/容量、待烤与烘焙中工单、配方耗时）。任一变化旧版本即标「已过期」并逐条列出变化明细，可一键基于最新数据重算；较慢的旧计算不能覆盖新版本。
- 并发保存：保存走 schedule_state 行锁 + baseVersionNo 乐观校验——两名操作员同时保存只保留一个版本，失败方收到 409 后自动刷新，看到最新顺序与冲突提示；历史版本可回看（只读）。

## 故障接管链路

烤箱故障（设备页「置故障」）后，该炉上的「待烤 / 烘焙中」工单会停滞：

- 入口：烤箱列表「故障接管」按钮、烤箱详情抽屉、烘焙工单看板顶部异常条与故障炉工单卡片。
- 预览：弹窗展示故障炉上每张待烤/烘焙中工单，逐张选择替代烤箱；不可用的炉子置灰并给出原因。
- 风险分级：待烤工单迁移后仍为待烤（中风险）；烘焙中工单迁移后保留状态与**原开始时间**到替代炉续烤（高风险，前端红色提示）。
- 校验：替代烤箱必须空闲、容量不小于工单烤盘数、且不能再接收第二张烘焙中工单。
- 原子性：一次可迁多张，**任一张不满足条件则整批不落库**，错误信息定位到具体工单与原因；同一替代炉被两批接管同时选中时，靠数据库行锁串行裁决，只成功一批，失败批不留半迁移数据。
- 修复：故障炉修复为空闲后，未迁移工单仍归属本炉；再次故障可继续接管，已迁移工单不会被重复迁回或重复占用容量。
