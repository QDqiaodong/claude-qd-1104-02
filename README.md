# 烘焙坊 · 烤箱设备与面包批次

烘焙坊生产管理：管理烤箱设备、面包配方，并以看板方式排产烘焙工单（待烤 → 烘焙中 → 已出炉 → 已质检），质检完成后出货（门店 / 外卖）。

## 生产排产（建议顺序 + 版本）

「排产」页把尚未开始（待烤）的工单排成可解释的建议顺序，排产只是建议，**绝不回写工单状态与故障接管归属**：

- 计算在服务端：按优先级逐单分配到「预计完成最早」的容量足够烤箱；故障烤箱不参与，占用烤箱按当前烘焙中工单预计出炉时间释放后参与，一炉同时只排一张。
- 每条建议展示：预计开始/完成时间、建议占用烤箱（与实际归属并列，建议改挂不改归属）、容量占用、截止时间风险（正常 / 紧张 / 无截止时间）与排入解释。
- 未排入区：没有可用烤箱、容量不足（容量预警）、预计逾期的工单如实留在未排入区并给出原因，不伪装成已安排。
- 优先级：操作员拖动调整（已开始/已完成的工单不在列表即不可拖），拖动后由服务端试算；默认按交付截止时间升序。
- 版本：保存时落库版本头 + 明细快照。烤箱状态、工单烤盘数或交付截止时间变化后，数据指纹变化，旧版本标为「过期」，可基于最新数据重算后另存新版本。
- 并发：保存时锁定 `bake_schedule_meta` 单行，校验版本基线（baseVersionId）与数据指纹（fingerprint）——两名操作员同时保存只保留一个版本，较慢的旧计算也不能覆盖新版本；失败方刷新后看到最新顺序与冲突提示。

## 故障接管链路

烤箱故障（设备页「置故障」）后，该炉上的「待烤 / 烘焙中」工单会停滞：

- 入口：烤箱列表「故障接管」按钮、烤箱详情抽屉、烘焙工单看板顶部异常条与故障炉工单卡片。
- 预览：弹窗展示故障炉上每张待烤/烘焙中工单，逐张选择替代烤箱；不可用的炉子置灰并给出原因。
- 风险分级：待烤工单迁移后仍为待烤（中风险）；烘焙中工单迁移后保留状态与**原开始时间**到替代炉续烤（高风险，前端红色提示）。
- 校验：替代烤箱必须空闲、容量不小于工单烤盘数、且不能再接收第二张烘焙中工单。
- 原子性：一次可迁多张，**任一张不满足条件则整批不落库**，错误信息定位到具体工单与原因；同一替代炉被两批接管同时选中时，靠数据库行锁串行裁决，只成功一批，失败批不留半迁移数据。
- 修复：故障炉修复为空闲后，未迁移工单仍归属本炉；再次故障可继续接管，已迁移工单不会被重复迁回或重复占用容量。
